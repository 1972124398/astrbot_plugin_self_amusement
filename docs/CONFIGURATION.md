# 配置参考

## 一套目标与一套节奏

“可以主动搭话的会话”使用 AstrBot 原生 UMO 多选控件，群聊与私聊放在同一个列表。也可先在目标会话发送 `/sid` 查询 UMO，或用管理员命令 `/amuse_here` 加入。

每次正常 AI 对话会在全局重置空闲计时。角色达到空闲时长后，可以选择一处会话琢磨话头，也可以只浏览或继续待着。

## 全部配置

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 启用后台活动 |
| `targets` | `[]` | 群聊与私聊共用的 UMO 列表 |
| `provider_id` | 空 | 留空跟随所选会话模型 |
| `idle_min_minutes` | `15` | 最早开始琢磨的空闲时间 |
| `idle_max_minutes` | `45` | 最晚开始琢磨的空闲时间 |
| `activities` | 全部五种 | 搭话、碎碎念、浏览、分享、等待 |
| `interests` | 日常趣事等 | 闲下来时会惦记的兴趣 |
| `behavior_preferences` | 空 | 补充日常表达偏好 |
| `browse_enabled` | `true` | 允许联网查找与订阅浏览 |
| `rss_feeds` | Solidot、IT 之家 | RSS / Atom 订阅地址 |
| `feed_max_age_hours` | `72` | 过滤有日期的陈旧订阅条目 |
| `global_gap_minutes` | `20` | 主动发话的全局最小间隔 |
| `target_gap_minutes` | `60` | 任一会话再次收到主动消息的最小间隔 |
| `max_unanswered` | `2` | 未接话时主动说几次后暂歇，0 不限制 |
| `unanswered_backoff_minutes` | `180` | 无人接话后的暂歇时间 |
| `daily_limit` | `12` | 所有会话当天合计次数，0 不设上限 |
| `quiet_hours` | `00:00-08:00` | 主机本地时间的安静时段，留空全天可用 |
| `message_length` | `220` | 正文长度，分享链接另附 |
| `repeat_window_hours` | `24` | 避开相似开场及旧链接的回看时段 |
| `generation_timeout_seconds` | `60` | 一轮计划、联网与生成的超时 |
| `web_timeout_seconds` | `15` | 搜索或订阅读取超时 |
| `send_timeout_seconds` | `30` | 等待平台发送结果的超时 |
| `retry_minutes` | `10` | 活动失败后多久再试 |
| `check_seconds` | `30` | 后台检查间隔 |

所有分钟、次数和表达配置都对整个目标列表统一生效。目标各自记录上次发话和有没有人接话，以便同一套设置能自然轮换着使用。

## 常见问题

### 没有主动发消息

用 `/amuse_status` 查看状态。检查目标列表、安静时段、空闲时间和模型配置。角色也可能选择了等待或只浏览，这些活动不会向目标发送消息。

默认需要正常对话空闲 15～45 分钟，刚安装时也会先等待一段时间。平台需要支持主动推送，AstrBot 已关闭的会话、LLM 和插件范围也会影响自动活动。

### 想更爱搭话，或者更像在自己玩

多保留 `chat`、`mutter` 会更常产生聊天话头。保留 `browse` 与 `wait` 会有更多自己逛逛、看完先待着的空间。填写具体兴趣与偏好有助于产生有趣内容。

### 有人不接话还会继续说吗

默认连续两次后先歇三小时。回复进入正常 AI 对话后会清除当前会话的未接话计数。未唤醒 AI 的群内闲聊不计为一次正常 AI 对话。

### 只想预览

使用 `/amuse_preview`，会在当前命令回复里展示。预览仍会产生模型调用，若选到浏览或分享还会读取联网资料。

### 搜索和新闻从哪里来

优先使用 AstrBot 已启用的内置搜索配置。搜索不可用时回落到 RSS，默认源可自由替换。RSS 是订阅浏览，模型可以从实际条目里找话头；用户配置的搜索服务负责按关键词查询。

### 和其他主动聊天插件同时使用

两者的发起计划独立。自娱自乐会留意标准 LLM 对话钩子和回复，主动规划期间若有对话进入，就把这次发话放下。自娱自乐生成的消息只由本插件发送一次。

### 微信发送失败

先确认普通聊天及微信 Native 连接正常。群聊发送能力取决于所用适配器。未确认的发送尝试也会保留间隔，避免立即重发同一条消息。
