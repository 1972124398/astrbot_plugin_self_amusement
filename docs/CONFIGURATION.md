## 一套目标与一套节奏

“可以主动搭话的会话”使用 AstrBot 原生 UMO 多选控件，群聊与私聊放在同一个列表。也可先在目标会话发送 `/sid` 查询 UMO，或用管理员命令 `/amuse_here` 加入。

每次正常 AI 对话会在全局重置空闲计时。角色达到空闲时长后，可以选择一处会话琢磨话头，也可以只浏览或继续待着。

“记住和谁相处开心”会保留各会话最近几次相处的感觉、共同兴趣与下次想聊的话头。闲下来选择目标时会自然偏向相处愉快的地方。想让它更愿意认识不同会话，可以选温和；想让它更明显地找聊得来的，可以选更随心。

## 全部配置

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 启用后台活动 |
| `targets` | `[]` | 群聊与私聊共用的 UMO 列表 |
| `provider_id` | 空 | 留空跟随所选会话模型 |
| `reflection_provider_id` | 空 | 可为后台相处回想选择独立模型 |
| `chat_first` | `true` | 有人聊天时先陪人，暂缓后台生成 |
| `background_after_chat_seconds` | `10` | 聊天结束后留一点空隙再继续后台活动 |
| `reflection_merge_seconds` | `20` | 连续对话合并一小会儿再回想 |
| `remember_chemistry` | `true` | 后台回想每段相处，记住聊起来的感觉 |
| `preference_strength` | `natural` | 温和、自然偏心、更随心三种倾向 |
| `unanswered_policy` | `wait_for_reply` | 默认冷场后先放下，也可选 `occasionally` 偶尔再聊 |
| `idle_min_minutes` | `15` | 最早开始琢磨的空闲时间 |
| `idle_max_minutes` | `45` | 最晚开始琢磨的空闲时间 |
| `activities` | 全部五种 | 搭话、碎碎念、浏览、分享、等待 |
| `interests` | 日常趣事等 | 闲下来时会惦记的兴趣 |
| `behavior_preferences` | 空 | 补充日常表达偏好 |
| `browse_enabled` | `true` | 允许联网查找与订阅浏览 |
| `rss_feeds` | Solidot、IT 之家 | RSS / Atom 订阅地址 |
| `feed_max_age_hours` | `72` | 过滤有日期的陈旧订阅条目 |
| `global_gap_minutes` | `20` | 主动发话的全局最小间隔 |
| `target_gap_minutes` | `60` | 任一会话再次收到主动消息的最小间隔 |
| `max_unanswered` | `2` | 未接话时主动说几次后先放下，0 不限制 |
| `unanswered_backoff_minutes` | `180` | 选择偶尔再聊时使用的暂歇时间 |
| `daily_limit` | `12` | 所有会话当天合计次数，0 不设上限 |
| `quiet_hours` | `00:00-08:00` | 主机本地时间的安静时段，留空全天可用 |
| `message_length` | `220` | 正文长度，分享链接另附 |
| `repeat_window_hours` | `24` | 避开相似开场及旧链接的回看时段 |
| `generation_timeout_seconds` | `60` | 一轮计划、联网与生成的超时 |
| `reflection_timeout_seconds` | `30` | 后台回想相处感受的等待时间 |
| `web_timeout_seconds` | `15` | 搜索或订阅读取超时 |
| `send_timeout_seconds` | `30` | 等待平台发送结果的超时 |
| `retry_minutes` | `10` | 活动失败后多久再试 |
| `check_seconds` | `30` | 后台检查间隔 |

所有分钟、次数和表达配置都对整个目标列表统一生效。目标各自记录上次发话和有没有人接话，以便同一套设置能自然轮换着使用。

## 常见问题

### 没有主动发消息

用 `/amuse_status` 查看状态。检查目标列表、安静时段、空闲时间和模型配置。角色也可能选择了等待或只浏览，这些活动不会向目标发送消息。

默认需要正常对话空闲 15～45 分钟，刚安装时也会先等待一段时间。平台需要支持主动推送，AstrBot 已关闭的会话、LLM 和插件范围也会影响自动活动。

### 想更爱搭话，或者更像在自己玩

多保留 `chat`、`mutter` 会更常产生聊天话头。保留 `browse` 与 `wait` 会有更多自己逛逛、看完先待着的空间。填写具体兴趣与偏好有助于产生有趣内容。

### 有人不接话还会继续说吗

默认连续两次后先放下这个会话，等对方再次进入正常 AI 对话后才重新考虑主动找。可改成歇一阵后偶尔想起再聊，默认等待三小时。未唤醒 AI 的群内闲聊不计为一次正常 AI 对话。

对方回复时会先重新打开相处机会，再由后台回想判断有没有变得开心、舒服或更想靠近。简单回一个字并不会自动形成亲近印象，曾经不舒服的相处也可以随着真诚的新互动慢慢修复。

### 想看看它为什么更愿意找某个会话

管理员用 `/amuse_social` 查看当前会话留下的感觉、共同兴趣和没聊完的话题，或用 `/amuse_status` 看最近几处相处印象。希望放下旧印象时，可在当前会话使用 `/amuse_forget`。

### 从 0.1.0 更新

原有目标、兴趣和时间配置会保留。新的相处记忆从后续正常对话开始形成。无人接话默认策略改为等对方回来，若希望沿用以前的暂歇后再试，可把“总是没人接话时怎么办”选为“歇一阵后偶尔想起再聊”。

### 只想预览

使用 `/amuse_preview`，会先收到接单提示。后台想好后再向发起命令的同一会话展示结果，期间可以继续正常聊天。预览仍会产生模型调用，若选到浏览或分享还会读取联网资料。已经有一个预览时，会提示等待已有结果。

### 聊天时后台会不会抢着说话

默认开启“有人聊天时先陪人”。前台开始正常对话时，尚未发出的闲话会放下，相处回想与预览会暂缓。聊天暂歇后再继续，新的对话优先使用最新快照。

已经开始向平台发送的消息会等待发送结果。没有真正发出的计划被聊天打断时，不会当作一次对方没回应的主动发言。

### 想减少后台模型竞争

可以为“后台回想相处感受的模型”选择独立 Provider，也可以增加“聊完后先等几秒，再回想相处感受”，把相邻几句一起回想。使用相同服务仍然共享服务端额度和并发，客户端暂缓或取消并不保证服务端立即停止计算。

### 从 0.2.0 更新

旧的相处印象、目标和节奏会保留。默认新增聊天优先、暂歇后的后台恢复、相邻回合合并，以及后台预览。配置窗口可以调整这几项行为。

### 搜索和新闻从哪里来

优先使用 AstrBot 已启用的内置搜索配置。搜索不可用时回落到 RSS，默认源可自由替换。RSS 是订阅浏览，模型可以从实际条目里找话头；用户配置的搜索服务负责按关键词查询。

### 和其他主动聊天插件同时使用

两者的发起计划独立。自娱自乐会留意标准 LLM 对话钩子和回复，主动规划期间若有对话进入，就把这次发话放下。自娱自乐生成的消息只由本插件发送一次。

### 微信发送失败

先确认普通聊天及微信 Native 连接正常。群聊发送能力取决于所用适配器。未确认的发送尝试也会保留间隔，避免立即重发同一条消息。
