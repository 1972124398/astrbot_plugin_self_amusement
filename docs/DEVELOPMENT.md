# 工作方式与开发

[返回首页](../README.md) · [配置参考](CONFIGURATION.md)

后台维持一个全局闲暇状态。普通 `on_llm_request` 和 `on_llm_response` 只留下有限长度的文字快照、活动标记和待回想任务。人格解析、目标整理、相处回想、闲逛计划、联网读取、发言生成和状态保存由后台处理。其他主动回复采用 `proactive:` 标识时也会让全局空闲重新计时。

## 后台推进方式

闲逛调度、相处回想、状态保存分别拥有独立任务。一个慢回想不会占住整条闲逛流程。保存使用合并写入与后台线程，正常对话钩子只通知有变化。

正常聊天开始时会标记当前前台回合，取消尚未发送的闲话生成，并暂缓后台回想。聊天完成后留出可配置的空隙。`on_agent_done` 补充清理回合状态，异常中断的遗留等待标记也会在后续检查中失效。

每个会话的待回想任务合并为最近一份，并在对话暂歇后处理。被其他会话聊天打断的有效回想可继续排队；已经出现更新互动的旧回想会被丢弃。回想可配置独立 Provider。

预览命令先返回接单提示，由后台任务生成并投递到发起预览的会话。遇到正常聊天时，未完成的预览生成暂缓，随后恢复。预览与自主发言的次数分开处理。

空闲到期后，从统一目标列表中选取当前适合的一处会话，参考该会话人格、最近背景、自己的近期活动与兴趣进行计划。相处开心、有被接住的感觉和愿意继续交流的会话会更容易被选中，敷衍、聊得累和无人接话的会话会降低吸引力。

## 相处印象

普通对话完成后，后台按会话回想自己的感受，保留最近六次简短印象。回想用开心、愉快、平淡、疲惫、受伤和更想靠近或有所保留等语义描述，另外记下共同兴趣及没聊完的话题。

选择时综合最近几次感受与当前意愿，保留一点余韵。正常回复只是重新打开相处机会，后台仍会结合语境判断有没有重新熟络。默认达到无人接话次数后，主动发起先放下，等对方再次正常交流。明确说忙会暂缓，明确不想被主动联系时会等对方回来。

回想在后台执行，每个会话相邻的未处理回合合并到最近一次。前台快照只包含当前人格标识与系统提示，实际解析在回想时进行；新的互动进入后，晚到的旧印象不会覆盖新状态。

计划与正文会参考当前会话的相处感受、共同兴趣和未完话头。取得订阅或检索材料后，分享优先考虑共同兴趣，保留实际来源链接。

搭话与碎碎念会生成一条正文，分享先取得真实材料再生成，浏览和等待可以没有消息。闲逛活动自身保持单次推进，相处回想和状态保存各自进行，正常对话直接继续。

## 人格与情绪

人格通过 AstrBot 的 `resolve_selected_persona()` 解析，保留目标会话的人格选择。WebChat 使用框架对应的默认人格。

检测到已启用的短期共享情绪插件时，计划会参考它的心境，正文生成调用其 `apply_mood()` 附加当前表达。合成事件的 ID 以 `proactive:` 开头，因此不会作为新的用户情绪刺激。

生成直接使用 `Context.llm_generate()`，自动发送使用 `Context.send_message()`。WeChat Native 使用已安装适配器的确认式 `send_chain()`。本插件使用自身后台状态，主动请求无需再次进入消息合并或 Codex 委派等完整对话钩子。

普通回复会收到同一会话最近主动说过的话作为临时 `TextPart`。本插件保存自己的最近 12 次活动，供后续接话和去重。WebChat 主动消息的保存由其适配器处理。

## 状态与发送

运行数据位于 `data/plugin_data/astrbot_plugin_self_amusement/leisure.json`，包括全局闲暇状态、活动记录和每个目标的相处印象、共同兴趣及未完话头。写入通过后台线程及原子替换完成。

发送前先记录尝试与间隔，重启后不会回放未确认发送。平台通用接口返回成功时只代表找到了路由，具体送达能力由平台决定。微信 Native 可提供发送确认。

计数使用 AstrBot 主机本地日期。全局空闲、发话间隔、目标间隔、安静时段、无人接话暂歇和每日总量都在配置窗口可改。

## 验证

```shell
python -m unittest discover -s tests -v
```

核心测试覆盖共享节奏、群聊与私聊混合目标、等待和浏览、来源链接、RSS/Atom、安静时段、退让间隔、发送前活动变化以及重启后的待发送状态。

安装了 AstrBot SDK 的 Python 环境还会验证真实 `ProviderRequest`、合成的群聊/私聊事件、人格解析、短期情绪接入和配置 schema。

开发中使用独立状态与已配置模型进行过生成预览，使用公开 RSS 实测读取。真实群聊或私聊的自动投递需要安装后选择目标并实际验证，平台差异以适配器能力为准。

0.2.0 还用独立状态与真实模型预览了愉快接梗、敷衍接话、明确要求停止主动联系，以及后续真诚道歉和重新聊起共同兴趣的场景。观察到愿意主动靠近、降低兴致、让出空间和逐步回暖的不同印象。

0.3.0 在本地通过慢回想与闲逛独立推进、聊天到来后取消未发出的计划、回想合并、跨会话打断后继续、慢写盘下的前台响应、后台预览、重载任务清理及发送前计划撤销等验证。

100 轮本地钩子测试中，请求与回复钩子合计中位耗时约 0.011 毫秒，95 分位约 0.018 毫秒，钩子内模型调用为零。该数字只描述插件钩子自身的耗时，不包含聊天模型或平台处理时间。
