# 工作方式与开发

[返回首页](../README.md) · [配置参考](CONFIGURATION.md)

后台维持一个全局闲暇状态。普通 `on_llm_request` 和 `on_llm_response` 只观察真实对话并重置空闲计时，收集已配置目标的近期文字背景。其他主动回复采用 `proactive:` 标识时也会让全局空闲重新计时。

空闲到期后，从统一目标列表中选取当前适合的一处会话，参考该会话人格、最近背景、自己的近期活动与兴趣进行计划。近期已主动发过的目标与无人接话的目标会降低选择优先级。

搭话与碎碎念会生成一条正文，分享先取得真实材料再生成，浏览和等待可以没有消息。全流程在后台串行执行，正常对话直接继续。

## 人格与情绪

人格通过 AstrBot 的 `resolve_selected_persona()` 解析，保留目标会话的人格选择。WebChat 使用框架对应的默认人格。

检测到已启用的短期共享情绪插件时，计划会参考它的心境，正文生成调用其 `apply_mood()` 附加当前表达。合成事件的 ID 以 `proactive:` 开头，因此不会作为新的用户情绪刺激。

生成直接使用 `Context.llm_generate()`，自动发送使用 `Context.send_message()`。WeChat Native 使用已安装适配器的确认式 `send_chain()`。本插件使用自身后台状态，主动请求无需再次进入消息合并或 Codex 委派等完整对话钩子。

普通回复会收到同一会话最近主动说过的话作为临时 `TextPart`。本插件保存自己的最近 12 次活动，供后续接话和去重。WebChat 主动消息的保存由其适配器处理。

## 状态与发送

运行数据位于 `data/plugin_data/astrbot_plugin_self_amusement/leisure.json`。写入通过后台线程及原子替换完成。

发送前先记录尝试与间隔，重启后不会回放未确认发送。平台通用接口返回成功时只代表找到了路由，具体送达能力由平台决定。微信 Native 可提供发送确认。

计数使用 AstrBot 主机本地日期。全局空闲、发话间隔、目标间隔、安静时段、无人接话暂歇和每日总量都在配置窗口可改。

## 验证

```shell
python -m unittest discover -s tests -v
```

核心测试覆盖共享节奏、群聊与私聊混合目标、等待和浏览、来源链接、RSS/Atom、安静时段、退让间隔、发送前活动变化以及重启后的待发送状态。

安装了 AstrBot SDK 的 Python 环境还会验证真实 `ProviderRequest`、合成的群聊/私聊事件、人格解析、短期情绪接入和配置 schema。

开发中使用独立状态与已配置模型进行过生成预览，使用公开 RSS 实测读取。真实群聊或私聊的自动投递需要安装后选择目标并实际验证，平台差异以适配器能力为准。
